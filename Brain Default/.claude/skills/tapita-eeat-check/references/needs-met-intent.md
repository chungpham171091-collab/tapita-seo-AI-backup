# Search Intent and Needs Met (QRG Parts 2-3)

Contents: 1. Key terms · 2. Interpreting the query · 3. Intent types · 4. Needs Met scale · 5. PQ vs NM · 6. Freshness · 7. Specificity, product, local, language · 8. SEO intent-fit checklist

## 1. Key terms (12.1)

- **Query**: what the user types/speaks/photographs.
- **Locale**: language + country of the task (e.g. vi-VN). **User location**: city-level when relevant.
- **Result block** (what appears on the SERP: title, snippet, special blocks) + **landing page**.

## 2. Interpreting the query (12.2-12.6)

- Research the query; don't assume the current top results are the only meanings.
- Locale changes expectations; ask "would people in another city/country want something different?"
- Explicit location in the query ([hotels Đà Nẵng]) overrides user location.
- Interpretations: **dominant** (what most mean), **common**, **reasonable minor**, **unlikely minor**, **no-chance** (off-topic even if words match).
- Respect important qualifiers: [non emergency number] ≠ emergency number; [is egg salad healthy] wants health info, not recipes. Keyword matching ≠ relevance.
- Meanings change over time: assume users want the current/latest model, event, figure unless the query says otherwise.

## 3. Intent types (12.7)

- **Know**: learn about a topic. **Know Simple**: one short, agreed answer fitting 1-2 sentences or a short list (height, date, symbol). Broad, ambiguous, controversial, opinion, browsing or inspiration queries are not Know Simple.
- **Do**: accomplish something - buy, download, calculate, pay, watch, take a test; can be open-ended (browsing ideas).
- **Website**: reach a specific site/page (the "target").
- **Visit-in-person**: a specific business or a category nearby; user location matters.
- Many queries have multiple intents (e.g. [citibank] = visit a branch or bank online).

## 4. Needs Met scale (13.0-13.6)

| Rating | Meaning |
|---|---|
| Fully Meets | Only when the query clearly seeks one specific result (a site, page, or Know Simple fact) and nearly all users would be fully satisfied. Be conservative; verify accuracy and consensus |
| Highly Meets | Very helpful for a dominant, common or reasonable minor intent. High bar: not for untrustworthy or outdated pages |
| Moderately Meets | Helpful for such an intent |
| Slightly Meets | Less helpful for a main intent, or helpful only for an unlikely minor intent |
| Fails to Meet | Fails nearly all users: off-topic, no-chance interpretation, useless, harmful, untrustworthy |

Plus half steps. Rating the block: for web results, the landing page matters (a click is needed); for special blocks, the block content, plus landing page if users would click.

## 5. PQ vs NM (14.0)

- PQ ignores the query; NM depends on it.
- Very low PQ pages (gibberish, scams) = Fails to Meet - except clear website-intent queries, where the requested site is Fully Meets.
- Useless is useless: high PQ doesn't save an irrelevant result.
- A snippet showing wrong info for the query (piano octaves for a guitar query) = Fails, even with a good landing page. → For SEO: title/meta/featured-snippet text must be accurate for the query.

## 6. Freshness (18.0)

Needs current results: breaking news; recurring events (elections, tournaments, tax forms, schedules); current figures (population, prices, airfares, next holiday); products (latest model). Outdated content for these queries lowers NM. → Show dates, update yearly content, keep prices/specs current.

## 7. Other NM factors

- **Specificity (17.0)**: for broad queries ([credit cards], [restaurants]) popular, prominent options are very helpful; a more specific page can still be very helpful if it's a prominent option.
- **Product queries (21.0)**: many users research and browse before buying - pages that help compare, browse, read reviews and specs earn high NM. PQ on product pages needs extra care.
- **Visit-in-person (22.0)**: results must suit user location; distance matters for most local categories.
- **Misspellings / names (19.0)**: interpret the likely intended query.
- **Language (23.0)**: in non-English locales, English results may be acceptable only when users there would use them; localized content is usually better.
- **Website + local intent (16.1)**: both a branch listing and the official site can be very helpful.

## 8. SEO intent-fit checklist

- [ ] Dominant intent identified; page type matches it (guide vs category vs product vs tool vs local page)
- [ ] Important qualifiers in the keyword are answered explicitly
- [ ] The main answer/action is visible near the top (no filler before it)
- [ ] Covers common and reasonable minor intents with sections or links where sensible
- [ ] Title and meta description accurately describe the MC (no bait, no mismatch)
- [ ] Fresh where the query needs freshness (date shown, current year data, latest models)
- [ ] For commercial queries: supports browsing/comparison (filters, specs, reviews, prices, availability)
- [ ] For local: address, hours, map, local relevance
- [ ] Language and locale match the target market
- [ ] Would a user stop searching after this page? If not, what's missing?
